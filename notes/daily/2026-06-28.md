## What got done

- **`Operator` ABC** — `open`/`next`/`close` as `@abstractmethod`. Chose abstract over a base no-op default *on purpose*: a silent no-op default is a trap in the Volcano model, because every non-leaf operator's `open`/`close` must **propagate to children**; a forgotten override would then silently skip opening a child (→ zero rows, no error). Abstract makes "forgot to wire it up" fail **loud** (can't instantiate) instead of **quiet**. That design call paid off immediately — it caught a missing `close()` at construction time.
- **`SeqScan`** — streams one row per `next()` from a CSV via a live `csv.reader` (no `list(...)` materialization), maps each row to a `dict` keyed by header, signals exhaustion by returning `None`, releases the file handle in `close()`.
- **Attacking test** (`tests/test_seqscan.py`) — asserts the **full ordered row list** in one compare (catches reorder/mangle/miscount) **and** post-exhaustion `None`. Both assertions **mutation-proven**: breaking empty→`None` reddened the sequence assert; returning a stale row at exhaustion reddened the post-exhaustion assert. Restore was byte-clean. 34 tests green.

## Where it lied / under-tested (the real lesson — green misled at FOUR points)

Green never once told the truth on its own this slice. Every step, the by-hand probe or the mutation check is what actually caught it:

1. **`next()` returned `{}`** — `__init__` set `self.cols` via `open()`, then the next line clobbered it back to `[]`. Caught by the by-hand probe (printed empty dict), not a test.
2. **`next()` returned ALL rows in a list** — a `while True` accumulator inside `next()`. This *inverts the whole Volcano model* — one call = whole table in memory. The probe output (a giant list) caught it. Classic "shipping the easy half": correct-looking output, wrong concept.
3. **empty→`None` path had zero coverage** — I kept the feature but the fixture had no empty field, so the branch never executed. Green "confirmed" an unexercised path. Caught on review; fixed by adding a `,25,India` fixture row + assertion.
4. **Tautological post-exhaustion assert** — `if row == None: assert row == None`, an assertion that *cannot fail* inside the branch that guarantees it. Pure "tests-that-confirm-not-attack." Caught on review; replaced with a real second-call check, then mutation-proven.

Plus: reported **"I am done"** once while the `"null"` coercion was still un-reverted (the code edit never happened). The verify step caught it — exactly the "done-when-it-isn't" self-deception the contract exists to kill.

## Decisions

- **NULL handling — scope-crept, then disciplined.** First cut coerced both `""` and the literal text `"null"` → `None`, plus `.strip()` on every value. None of it was in the slice.
  - **`"null"`-text coercion: reverted** — it's a bug. The 4-char string is real data; no engine coerces it by default (Postgres/DuckDB use the *empty* field, opt-in marker otherwise). Lossy + silent.
  - **`.strip()`: reverted** — same principle, smaller; the scan should return source bytes faithfully, trimming is a config policy for later.
  - **empty `""` → `None`: KEPT, deliberately + now tested** — it's the defensible default real engines use. Logged the residual risk: it emits a `None` whose consumer (the WHERE evaluator) doesn't exist yet, so three-valued logic isn't optional later — it's already load-bearing.
  - Full reasoning backlogged as **SCAN-1** (configurable marker + three-valued logic, to build *with* the WHERE evaluator).
