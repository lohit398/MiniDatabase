## The lesson that actually mattered today

**Green lied three times in one session; the by-hand probe caught all three.**
1. AND combinator missing — suite green because no test fed an `AND`.
2. Precedence inverted (AND at root) — suite green because the test asserted the *inverted* shape.
3. "Fixed it" still inverted — same reason.

Root cause of #2/#3: **the test was written to match what the code printed, not what the spec requires.** A test derived from the code can only ever confirm the code. The fix: derive the expected tree from SQL semantics *first* (`a AND b OR c` ≡ `(a·b)+c` → root is OR), write the assertion, watch it go **red** against the current parser, *then* make it pass. Red-first is the proof the test has teeth.

Precedence model locked: **loosest = root = parsed outermost = evaluated last; tightest = deepest = evaluated first.** AND binds tighter, sits deeper, evaluates first.
